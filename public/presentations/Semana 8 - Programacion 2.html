Arquitectura N-capasSeparación de responsabilidades

Una capa agrupa responsabilidades técnicas similares.

PresentaciónUI y validación de entrada
→
NegocioReglas y casos de uso
→

N-capas no exige un número fijo de capas. Se agregan solo cuando una responsabilidad lo justifica.
Aplicación de tres capasFlujo de una operación

Registrar un usuario atraviesa las capas en orden.

01PresentaciónFormulario recoge y valida el formato del correo.
02NegocioServicio verifica reglas: correo único y contraseña válida.
03DatosRepositorio inserta el registro mediante una consulta parametrizada.
04RespuestaEl resultado vuelve al cliente sin exponer detalles internos.
Efectos de la separaciónDiseño mantenible

Separar capas reduce el acoplamiento.

Pruebas

Las reglas se prueban sin navegador ni base de datos real.

Cambios

Se sustituye una interfaz sin reescribir reglas de negocio.

Seguridad

Las credenciales permanecen en el servidor.

Escala

Cada capa puede crecer de forma independiente.

Desarrollo WebConceptos iniciales

Una aplicación Web se entrega mediante la red.

URL

Dirección que identifica un recurso: protocolo, dominio y ruta.

DNS

Resuelve un dominio a una dirección IP.

HTTP

Protocolo de solicitud y respuesta para recursos Web.

https://ejemplo.com:443/productos?id=7
Protocolos WebComunicación segura

HTTPS protege la comunicación HTTP mediante TLS.

HTTP

Define métodos, encabezados, códigos de estado y cuerpos de mensajes.

Puerto habitual: 80.

HTTPS

HTTP sobre una conexión cifrada y autenticada por TLS.

Puerto habitual: 443.

Datos sensibles, sesiones y credenciales deben transmitirse mediante HTTPS.
HTTPOperaciones sobre recursos

Los métodos expresan la intención de la solicitud.

GET

Obtener una representación.

POST

Crear o procesar una acción.

PUT / PATCH

Reemplazar o modificar.

DELETE

Eliminar un recurso.

GET /api/tareas → 200 · POST /api/tareas → 201 · recurso ausente → 404
Ciclo de una páginaSolicitud y renderizado

El navegador solicita recursos y construye la interfaz.

01URLEl navegador resuelve el dominio mediante DNS.
02SolicitudEnvía una petición HTTP/HTTPS al servidor.
03RespuestaRecibe HTML, CSS, JavaScript, imágenes o datos JSON.
04RenderizadoConstruye el DOM, aplica estilos y ejecuta scripts.
Transferencia de archivosFTP y alternativas

FTP transfiere archivos entre cliente y servidor.

FTP

Protocolo histórico de transferencia; no cifra por defecto.

SFTP

Transferencia sobre SSH con autenticación y cifrado.

Despliegue actual

También se publica mediante Git, CI/CD, APIs o proveedores cloud.

No confundir FTP con HTTP: FTP mueve archivos; HTTP entrega recursos a los navegadores.
