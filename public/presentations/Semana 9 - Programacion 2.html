Las etiquetas semánticas expresan el rol del contenido. Una etiqueta div solo agrupa elementos sin aportar significado.

Web ServersAtención de solicitudes

El servidor Web recibe una solicitud y produce una respuesta

Archivos estáticos

Entrega HTML, CSS, JavaScript, imágenes y documentos ya existentes.

Contenido dinámico

Ejecuta código que consulta datos o aplica reglas antes de responder.

Seguridad

Termina TLS, autentica solicitudes y limita acceso a recursos.

solicitud HTTP → ruta → aplicación → respuesta HTTP
HTTPSolicitud y respuesta

HTTP transporta mensajes entre cliente y servidor

GET /cursos/15 HTTP/1.1
Host: ejemplo.edu.gt
Accept: text/html
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>

Método

Expresa la operación: GET, POST, PUT, PATCH o DELETE.

Encabezados

Describen formato, autenticación, caché y negociación de contenido.

Cuerpo

Transporta HTML, JSON, archivos u otros datos cuando aplica.

ProtocolosWeb y transferencia

HTTPS protege HTTP; FTP transfiere archivos

Protocolo
Propósito
Seguridad
HTTP
Intercambiar recursos Web.
No cifra por sí mismo.
HTTPS
Intercambiar recursos Web sobre TLS.
Cifra y autentica la conexión.
FTP / SFTP
Transferir archivos a un servidor.
SFTP usa SSH; FTP no cifra por defecto.
Una aplicación no debe enviar sesiones, contraseñas o datos personales por HTTP sin TLS.

JavaScriptEventos y DOM

JavaScript responde a eventos y actualiza elementos del documento

const formulario = document.querySelector("#curso-form");

formulario?.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const datos = new FormData(formulario);
  console.log(datos.get("nombre"));
});
El evento submit permite validar o enviar los datos antes de que el navegador navegue a otra página.
JavaScriptComunicación asíncrona

Fetch consume un recurso HTTP sin recargar toda la página

const respuesta = await fetch("/api/cursos");
if (!respuesta.ok) throw new Error("No se pudieron obtener los cursos");

const cursos = await respuesta.json();
renderizarCursos(cursos);
fetch → Response → validación de estado → conversión de cuerpo → actualización de UI
Back End DevelopmentCódigo en el servidor

El back end protege reglas, acceso a datos y operaciones sensibles

Rutas

Asocian método y URL con una función que procesa la solicitud.

Servicios

Aplican reglas del dominio, validaciones y casos de uso.

Persistencia

Consulta o modifica datos sin exponer la tecnología al cliente.

El navegador nunca debe recibir credenciales de bases de datos ni decisiones de autorización que solo el servidor puede comprobar.
JSON filesIntercambio de datos

JSON representa objetos y listas con una sintaxis compacta

{
  "id": 15,
  "nombre": "Programación 2",
  "activo": true,
  "temas": ["MVC", "HTTP"]
}

Tipos

Objeto, arreglo, cadena, número, booleano y null.

Uso común

XML filesDatos marcados

XML organiza datos mediante etiquetas anidadas

<curso id="15">

  <activo>true</activo>

XML requiere un único elemento raíz, cierre correcto de etiquetas y valores de atributos entre comillas.

Patrón MVCSeparación en aplicaciones Web

MVC separa datos, presentación y coordinación de solicitudes

VistaHTML, CSS y pantalla
→
Controladorcoordina el caso de uso
→
Modeloreglas y datos
El objetivo es reducir acoplamiento. Cada parte cambia por motivos diferentes y debe tener una responsabilidad clara.
MVCModelo

El modelo representa el dominio, sus reglas y sus datos

Entidades

Objetos como Curso, Estudiante o Inscripción con atributos coherentes.

Reglas

Condiciones que deben mantenerse, como cupo disponible o correo único.

Repositorios

Abstraen la consulta y almacenamiento de las entidades.

modelo válido = datos consistentes + reglas del dominio satisfechas
MVCVista

La vista presenta información y captura acciones del usuario

Contenido

Renderiza datos que el controlador proporciona.

Interacción

Incluye enlaces, formularios, botones y mensajes de validación.

Sin reglas críticas

No autoriza operaciones ni garantiza integridad de datos por sí sola.

Una vista puede validar formato para orientar al usuario, pero el servidor conserva la validación definitiva.
MVCControlador

El controlador traduce una solicitud en una operación del sistema

01RecibeLee ruta, método, parámetros, cuerpo y contexto del usuario.
02ValidaComprueba formato y delega reglas de dominio al modelo.
03CoordinaInvoca servicios o repositorios necesarios para el caso de uso.
04RespondeSelecciona vista, redirección o representación JSON con su estado HTTP.
Regla de capasNavegabilidad MVC

La dependencia principal avanza de vista a controlador y de controlador a modelo

Vistadepende del controlador
Vista > Controlador
Controladordepende del modelo
Controlador > Modelo
Modelono depende de la vista

Beneficio

El modelo se prueba sin navegador y la vista se puede reemplazar con menor impacto.

Evitar

La vista no consulta la base de datos directamente. El modelo no genera HTML para una pantalla específica.

Ambientes de softwareConfiguración y despliegue

Un ambiente combina una versión del sistema con configuración y datos apropiados

Desarrollo

Cambios locales y depuración frecuente.

QA

Pruebas funcionales y técnicas controladas.

UAT

Usuarios aceptan que el sistema satisface su necesidad.

Producción

Servicio disponible para usuarios reales.

Cada ambiente requiere sus propias variables, credenciales, datos y controles de acceso. No se reutilizan secretos de producción en desarrollo.
Ambiente de desarrolloConstrucción y depuración

Desarrollo permite crear y verificar cambios con rapidez

Datos de prueba

Representan casos necesarios sin usar información personal real.

Herramientas

Depurador, recarga local, registros detallados y pruebas automatizadas.

Configuración

Variables locales y servicios simulados cuando una dependencia externa no está disponible.

Un cambio listo en desarrollo todavía no demuestra que funciona con la configuración ni los permisos de los ambientes posteriores.

ProducciónOperación real

Producción prioriza disponibilidad, seguridad, observabilidad y recuperación

Disponibilidad

El sistema atiende usuarios dentro de los niveles acordados.

Observabilidad

Recuperación

Copias de seguridad, migraciones reversibles y plan de respuesta reducen impacto.

Los registros de producción no deben exponer contraseñas, tokens ni datos personales innecesarios.
