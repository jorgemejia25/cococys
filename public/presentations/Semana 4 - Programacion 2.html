Rigor y precisión

En XML no hay margen para la improvisación: una etiqueta sin cerrar, un anidamiento incorrecto o un carácter mal escapado rompe el documento completo. El rigor es profesionalismo aplicado a los datos.

▹Bien formado. Cada etiqueta de apertura tiene su cierre; el anidamiento es exacto.
▹Precisión. Nombres, atributos y valores se escriben como se acordó — sin variantes improvisadas.
▹Consecuencia. Un XML inválido no se lee: la aplicación lanza XmlException.

Saber — Fundamentos INTRO

¿Qué es XML?

eXtensible Markup Language: lenguaje de marcado extensible. Describe datos, no presentación. La estructura es un árbol de elementos anidados.

▹Marcado — etiquetas que delimitan el significado de cada dato.
▹Extensible — usted define los nombres de las etiquetas según el dominio.
▹Árbol — un elemento raíz; hijos y nietos forman la jerarquía.
No es HTML
HTML presenta páginas. XML transporta y organiza información intercambiable.
Legible por humanos y máquinas
Texto plano con estructura explícita: fácil de inspeccionar y de parsear en C#.

Saber — SintaxisXML

Sintaxis XML

Cinco piezas que aparecen en casi todo documento bien formado.

Declaración
<?xml version="1.0" encoding="UTF-8"?> — opcional pero recomendada.
Raíz única
Un solo elemento raíz envuelve todo el documento.
Elementos
Pares <etiqueta>...</etiqueta> o vacíos <br/>.
Atributos
Metadatos en la etiqueta de apertura: id="1".
Comentarios
<!-- texto --> — no forman parte de los datos.
Anidamiento
Los hijos cierran antes que el padre. Orden estricto.

Saber — Diseño del documentoCOMPARACIÓN

Elementos vs atributos

Ambos guardan información; la diferencia es semántica y de estructura.

Elementos
Contenido principal. Pueden anidarse y crecer. Ideal para titulo, estado, descripción.
Atributos
Metadatos cortos en la etiqueta. Ideal para id, prioridad, códigos. No anidan.
Ejemplo elemento
<titulo>No enciende</titulo>
Ejemplo atributo
<ticket id="1" prioridad="alta">

Saber — Validación básicaWELL-FORMED

Bien formado

Un documento bien formado cumple reglas estructurales mínimas. Sin ellas, el parser no puede construir el árbol.

En C#: XElement.Parse / XDocument.Load lanzan XmlException si el XML está mal formado. Captúrela y muestre el mensaje.

1Una sola raíz en el documento.
2Toda etiqueta abierta se cierra.
3Anidamiento correcto (sin cruces).
4Atributos entre comillas.
5Nombres sensibles a mayúsculas (Ticket ≠ ticket).

Saber — API nativaSystem.Xml.Linq

XDocument en C#

Namespace System.Xml.Linq. Tres tipos que modelan el árbol XML en memoria.

XDocument
El documento completo: declaración + raíz. Entrada con Load / Parse.
XElement
Un nodo del árbol: nombre, valor, hijos y atributos.
XAttribute
Par nombre=valor en la etiqueta de apertura.

using System.Xml.Linq; — disponible en .NET sin paquetes extra.

Saber hacer — Lectura04-LeerXDocument

Lectura con XDocument

Flujo típico: cargar el archivo, tomar la raíz y recorrer los elementos hijos.

1XDocument.Load(ruta) — construye el árbol.
2doc.Root — elemento raíz.
3Elements("ticket") — hijos con ese nombre.
4Attribute("id") / Element("titulo") — datos.
aLoad → Root
bElements → foreach
cAttribute / Element → Value
Ejemplo — CódigoLECTURA

Ejemplo: lectura

Recorre cada ticket, lee atributos y elementos hijos, e imprime un resumen en consola.

▹Carpeta: 04-LeerXDocument
▹Operador ?. evita null si falta un nodo.
Program.cs — lectura
using System.Xml.Linq; var doc = XDocument.Load(ruta); foreach (var ticket in doc.Root!.Elements("ticket")) { string id = ticket.Attribute("id")?.Value ?? "?"; string titulo = ticket.Element("titulo")?.Value ?? ""; string estado = ticket.Element("estado")?.Value ?? ""; Console.WriteLine($"#{id} {titulo} — {estado}"); }

Saber — Serialización07-XmlSerializer

XmlSerializer

Convierte un objeto C# en XML y el XML de vuelta en objeto. Ideal cuando ya tiene una clase de dominio.

→Serialize — objeto → XML (archivo o stream)
←Deserialize — XML → objeto tipado
▹Requiere propiedades public y constructor sin parámetros
XDocument
Control fino del árbol: usted arma cada nodo.
XmlSerializer
Automático desde la clase: menos código, menos control de formato.
JSON
Saber — Otro formato nativoSystem.Text.Json

Puente a JSON

Misma idea que XmlSerializer: objeto ↔ texto. Formato distinto, API nativa System.Text.Json.

▹JsonSerializer.Serialize — objeto → JSON
▹JsonSerializer.Deserialize<T> — JSON → objeto
▹Muy usado en APIs web; XML sigue vivo en integraciones empresariales
Mensaje clave
Si entiende serializar/deserializar en XML, el salto a JSON es principalmente de sintaxis, no de concepto.
Ejemplo — Código08-JsonBasico

Ejemplo: JSON básico

Serializa un Ticket a JSON indentado y lo recupera con Deserialize.

▹using System.Text.Json
▹WriteIndented = true para lectura humana
Program.cs — JSON
using System.Text.Json; var original = new Ticket { Id = 10, Titulo = "Impresora sin papel", Estado = "Abierto" }; var opts = new JsonSerializerOptions { WriteIndented = true }; string json = JsonSerializer.Serialize(original, opts); var recuperado = JsonSerializer.Deserialize<Ticket>(json);

Resumen visualCOMPARACIÓN

XML vs JSON

◇
XML
Etiquetas anidadas, atributos, namespaces. Robusto para documentos e integraciones legacy.
{}
JSON
Pares clave:valor, arrays. Ligero y dominante en APIs REST modernas.
⇄
En C#
XDocument / XmlSerializer para XML; System.Text.Json para JSON. Misma competencia: procesar datos estructurados.
✓
Cuándo
XML si el sistema lo exige; JSON si consume/produce APIs web. Ambos bien formados.

Tip: namespaces correctos

No mezclar APIs. Cada formato tiene su espacio de nombres nativo.

System.Xml.Linq
XDocument, XElement, XAttribute. Lectura y escritura del árbol XML.
System.Text.Json
JsonSerializer. Serialización JSON nativa de .NET.
System.Xml.Serialization
XmlSerializer. Objeto ↔ XML automático.
Evitar confusión
No use APIs antiguas de XmlDocument salvo que el enunciado lo pida.
